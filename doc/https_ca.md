# `HTTPS`

`HTTP` 超文本传输协议的安全版本，通过在 `HTTP` 和传输层之间加入 `SSL/TLS` （安全套接字/传输层安全协议）来保障通信安全
使用 `HTTPS` 后，数据从客户端到服务器的整个过程中都被加密保护，只有通信双方才能解码数据

- 数据加密
    - 通过加密技术可以确保通信内容不会被第三方窃听
- 身份验证
    - 通过服务器证书验证服务器内容，防止中间人攻击
- B 校验
    - 确认数据是否在传输过程中被篡改

# `CA`

- `CA`
  - 数字证书认证机构，负责发放和管理数字证书，承担公钥合法性检验职责
- `CA` 证书
  - 由 `CA` 签发的数字证书，格式可能有所不同，最常用的是 `X.509`
  - `X.509` 证书编码格式
    - `PEM (Privacy Enhanced Mail)`
      - 文本格式，文件后缀 `.pem`，以 `-----BEGIN XXXXXX-----` 开始，内容为 `BASE64`
    - `DER (Distinguished Encoding Rules)`
      - 二进制格式，文件后缀 `.der`，不可读
    - 文件后缀
      - `.pem`
      - `.der`
      - `.crt`
        - 代表 `Certificate`，常用于 `UNIX` 系统，可能采用 PEM 或 DER 编码，大多数为 PEM 编码
      - `.cer`
        - 代表 Certificate，意为证书，常见于 `Windows` 系统，可能采用 PEM 或 DER 编码，大多数为 DER 编码
      - `.key`
        - 通常存放公钥或私钥，虽非 `X.509` 证书，但其编码格式可能为 PEM 或 DER
      - `.csr`
        - `Certificate Signing Request`，即证书签名请求，向权威证书颁发机构申请签名证书的请求，其主要包含一个公钥及附加信息

### 认证

- 单向认证
  - 适用于无需在通信层面对用户身份进行验证的场景，一般在逻辑层保证用户合法登录
  - 流程
    - 客户端发起 `HTTPS` 请求，将 `SSL` 协议版本的信息发送到服务端
    - 服务端发送本机 `CA` 证书（服务端公钥、签名）
    - 客户端拿到证书，校验证书合法性，验证可行之后取出公钥
    - 客户端发送自己支持的对称加密算法给服务器
    - 服务器选择加密程度最高的加密算法
    - 服务器将选择好的加密方式以明文的形式发送给客户端
    - 客户端随机生成一个随机数 `R`，用服务端密钥加密 `R`，发送给服务器
    - 服务器使用自己的私钥解密密文，得到密钥 `R`
    - 双方开始使用随机数 `R` 作为密钥进行通讯
- 双向认证
  - 通信双方需要互相校验身份
  - 流程
    - 客户端发起 `HTTPS` 请求，将 `SSL` 协议版本的信息发送到服务端
    - 服务端发送本机 `CA` 证书（服务端公钥、签名）
    - 客户端拿到证书，校验证书合法性，验证可行之后取出公钥
    - ***客户端发送客户端证书（客户端公钥、签名）***
    - ***服务器校验客户端证书，并得到客户端公钥****
    - 客户端发送自己支持的对称加密算法给服务器
    - 服务器选择加密程度最高的加密算法
    - ***服务器将选择好的加密方式，使用客户端公钥加密发送***
    - 客户端随机生成一个随机数 `R`，用服务端密钥加密 `R`，发送给服务器
    - 服务器使用自己的私钥解密密文，得到密钥 `R`
    - 双方开始使用随机数 `R` 作为密钥进行通讯
